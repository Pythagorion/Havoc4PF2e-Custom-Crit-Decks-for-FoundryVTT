# Architecture

## Folder layout

```
module.json                 Manifest (version, download URL, packs, languages)
scripts/
  main.js                   Entry point: settings, hooks, socket routing, public API
  constants.js              Module ID, template paths, decks, attack types, roll kinds
  settings.js               All game settings (world, user and client)
  default-cards.js          Text of the 196 cards shipped with the module (DEFAULT_CARDS)
  deck.js                   Card model, filters, drawing, discard pile, card rendering
  trigger.js                Reads PF2e chat messages and decides whether a deck triggers
  prompt.js                 GM chat prompt ("draw a card?") before a draw
  player-draw.js            Public draw: face-down cards dealt to everyone, a player picks
  apps/card-draw.js         GM draw window (draw, redraw, pick, decline, reveal)
  apps/card-manager.js      Settings menu: create, edit, import and export cards
  manual-draw.js            Draw without a roll (the bundled macro)
  reveal.js                 Posts the revealed card to chat, starts the automation
  compendium-links.js       Adds @UUID links for PF2e condition and action names
  utils.js                  Settings shortcuts, localization, text helpers
  automation/
    schema.js               Data model of automation steps (single source of truth)
    default-automation.js   Steps of all default cards, keyed by card ID
    index.js                getAutomation(), offerAutomation()
    apply.js                Plan building, descriptions, applying, undo
    review.js               GM review dialog (summary, edit, token selection)
    saves.js                Save requests, player rolls, outcomes
    placement.js            Movement: highlighted squares and the drop marker
    table-rolls.js          "Rolled at the table" dialogs for saves and damage
    results.js              Result chat message with the Undo button
templates/                  Handlebars templates (paths in constants.js TEMPLATES)
styles/critdeck.css         All styles
lang/en.json, lang/de.json  Translations (all keys start with HCD.)
packs/_source/macros/       Editable JSON source of the macro compendium
packs/macros/               Compiled LevelDB pack (generated by npm run pack)
tools/packs.mjs             Builds and extracts the compendium packs
```

## From roll to card

1. **Trigger** (`trigger.js`). On `createChatMessage`, only the active GM checks the message. That way each roll is evaluated once. `evaluateMessage` finds the d20 and the roll kind (attack, save, skill, other), and checks the trigger settings (naturals and/or degree of success, players only or all actors). It returns a *trigger* object:
   ```js
   { deck: "hit" | "fumble", rollKind, attackType, damageTypes: [], info: { actorUuid, tokenUuid, targetActorUuid, targetTokenUuid, itemId, spellRank, weaponDie, natural, ... } }
   ```
   `attackType` is `melee`, `ranged`, `unarmed`, `spell`, or `"none"` (`GENERAL_ONLY`) for rolls that aren't attacks.
2. **Prompt or draw.** With the `gmPrompt` setting at `ask`, the GM gets a chat prompt first (`prompt.js`). Otherwise `beginDraw(trigger)` (`player-draw.js`) runs straight away. It opens either the GM draw window (`apps/card-draw.js`) or a player draw, depending on the `playerDraw` setting.
3. **Filtering** (`deck.js`). `getPool(deck, filter)` returns the enabled cards matching a filter `{ attackType, damageTypes, excludeGeneral, matchDamage }`:
   - General cards always match, unless `excludeGeneral` is set.
   - Specific cards must match the attack type, if they have one.
   - Damage types only filter when the `useDamageTypes` setting is on, or `matchDamage` is set (the GM picked a type in the manual draw).
4. **Reveal** (`reveal.js`). `revealCard(card, info, { damageTypes })` posts the card to chat and calls `offerAutomation` without awaiting it.

## From card to effects

```
offerAutomation(card)                     automation/index.js
  getAutomation(card)                     card.automation ?? DEFAULT_AUTOMATION[card.id]
  buildPlan(steps, {card, info, ...})     apply.js – localize texts, resolve DCs, formulas,
                                          weapon damage type, find area creatures
  AutomationReview.wait(...)              review.js – GM applies, edits or skips
  runPlan(plan)                           saves.js
    applyPlan(plan)                       apply.js – APPLY[step.type] for each recipient
    postResult(...)                       results.js – whispered result with Undo
    requestSave(...)                      saves.js – for each save step and creature
      -> resolveSave -> runPlan(outcome steps, with info.saver*)
```

- **Plan.** A copy of the steps with everything resolved for this draw: localized names and texts, numeric DCs, formulas with placeholders filled in, area candidates (`candidates`, `chosen`). Steps whose recipient doesn't exist are switched off (`enabled: false`).
- **Creatures.** `resolveCreatures(info)` returns `{ self, target, saver }`, each `{ actor, token }` or `null`. `self` is the creature that rolled (and drew the card); `target` is the target of that roll. `saver` only exists while a save's outcome is applied.
- **Undo.** Every apply function pushes undo records (`created`, `value`, `reduced`, `move`) into `ctx.records`. They are stored in the result message's flags, and the Undo button runs `undoRecords`. Damage and healing are not recorded, because PF2e posts its own message with an undo button for those.
- **Saves.** A save step isn't applied in `applyPlan`; it is returned and rolled afterwards:
  - **A player owns the creature:** the player gets a chat card with a roll button.
  - **Otherwise:** the GM rolls right away.
  - **GMs who roll physical dice** can enter the degree of success instead (`table-rolls.js`, setting `cardRolls`).

  The request is stored in the message flags, so it survives a reload. Results from players reach the GM via the socket action `auto-save-result`.

## Sockets

All messages use the channel `module.havoc-critdeck` (`SOCKET`), routed by the prefix of `data.action` in `main.js`:

| Prefix | Handler | Used for |
| --- | --- | --- |
| `pd-` | `onPlayerDrawSocket` (player-draw.js) | Player draw state, picks, GM controls |
| `auto-` | `onAutomationSocket` (automation/saves.js) | Save results sent by players |
| anything else | `onSocketMessage` (reveal.js) | Reveal popups |

New socket actions should take an existing prefix, or get a new prefix plus a branch in `main.js`.
